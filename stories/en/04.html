RecordWeb · A story about reuse

One record.
Multiple contexts.

Why the same information doesn't need to be filed multiple times to work meaningfully and reliably across several business cases.

Multiple contexts don't mean multiple copies.
This story explains a core difference between container-thinking and a network of records. It's aimed at subject-matter leads, information management, records management, and architecture, while staying grounded in an understandable, person-centred situation.

Scene 1 · A figure that's needed more than once

Ms. Roth has a verified time series on CO₂ emissions.

The time series is subject-matter relevant. It forms a basis for the answer to parliament. But it isn't needed only there.

Later, a team needs the same data for a climate report. Shortly after, a media enquiry arrives. And the subject-matter strategy references it as well.

Scene 2 · The familiar solution

Today, the same foundation is often copied and filed multiple times.

Parliamentary answer

The time series is filed as an attachment or file in the answer dossier.

CO2_series_final.xlsx

Climate report

Another copy is saved in the dossier for the report.

CO2_series_final_v2.xlsx

Media enquiry

Another copy is shared or filed again for the response.

CO2_series_released.xlsx

The problem isn't the copy itself. It becomes a problem when it's later unclear: which version is authoritative? Where was it updated? Which copy belongs to which context?

Copies aren't inherently wrong; sometimes they're legally, technically, or organisationally necessary. The structural problem is uncontrolled multiplication, where versions drift apart and provenance must be reconstructed later.

Scene 3 · The same record, different relationships

RecordWeb gives the time series a stable reference point.

The time series is kept as a self-contained record. It stays the same piece of information, with one version, one responsible office, and one uniquely referenceable identity.

Scene 5 · Context isn't the same as context

The relationship explains why the same record matters here.

✓In the answer

The time series serves as the subject-matter foundation for answering a specific parliamentary question.

✓In the climate report

The same time series is used as data foundation for a longer-term analysis.

✓In the media enquiry

It provides a traceable reference for an external response.

It's not filing in a folder that explains the context. The explicit relationship explains what meaning the record has in this context.
This is the substantive core. Context isn't just a set of documents in the same place; a record can play different roles depending on whether it's a foundation, a result, a trigger, an evidence item, or a reference.

Scene 6 · When the foundation changes

A correction doesn't need to be added to every dossier.

A stable reference point doesn't make changes invisible. It creates the basis for recognising and assessing their effect in different contexts.
Earlier answers aren't rewritten retroactively. A later correction or new version becomes visible as a successor, and other cases can decide whether and how to respond.

Scene 7 · Less reconstruction, clearer responsibility

Reuse becomes more understandable for everyone involved.

With uncoordinated copies

  • Different file names and storage locations
  • Unclear or diverging versions
  • Repeated maintenance and update effort
  • Difficult provenance and relevance checks
  • Risk that context and responsibility blur

With linked records

  • One clear reference point for the information
  • Explicit relationships to several cases
  • Versions and successors are traceable
  • Targeted use instead of widely scattered duplicates
  • Responsibility stays with the accountable office
Even in a RecordWeb, some replication or derivatives may still be necessary. The architectural idea is that identity, provenance, and relationships shouldn't get lost through uncontrolled copying.

Scene 8 · From dossier to network

This is how a network of records grows.

The case gives people an understandable working and orientation view. The record stays self-contained, reusable, and linkable to other contexts at the same time.

This way, RecordWeb connects two legitimate needs: overview within a concrete case, and traceability across case boundaries.

Nobody needs to work in an abstract graph in everyday life. The case is the human perspective; the network is the architecture perspective. Both can be true at the same time without burdening the user with complexity.
